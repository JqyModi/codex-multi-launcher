订阅服务一键接入

不找中转站，也不用复制 API Key。

创建 Profile 时选择“订阅服务”，完成注册、购买和一次性授权后，App 会自动写入可用配置。支付宝、微信支付和国际银行卡可按支付页实际状态使用。

  • 新用户从注册直接进入套餐购买，不绕回后台首页。
  • 支付成功后自动恢复授权并回到桌面 App。
  • 同一套餐续期自动生效，更换套餐可在原 Profile 重新授权。

为什么需要它

不用再靠命令行记住不同工作区。

多窗口隔离

为不同项目创建独立的 `CODEX_HOME` 和 `user-data-dir`，减少配置互相影响。

第三方 API 配置

通过表单填写 Base URL、API Key 和模型，不再手动编辑 `config.toml`。

双击启动

每个 Profile 都会生成自己的启动器 App，像普通应用一样双击打开。

使用流程

从创建到打开，只保留必要步骤。

面向第一次配置的用户，默认继承已有 Codex 配置，并在关键位置给出测试和回退能力。

模型选择

能获取模型列表就选择，获取不到就手动填。

很多第三方服务商提供 `/models` 接口。Codex 多开助手会尝试解析返回结果中的模型 ID，并给出可点击选择。服务商不支持时，不影响手动填写模型。

  • 支持常见 `data`、`list`、`results` 返回结构。
  • 只使用明确的字符串 `id` 作为模型 ID。
  • 测试失败也允许继续生成，便于排查服务商兼容性。

本地安全

API Key 不进入诊断报告，也不写入启动脚本。

本地加密保存

API Key 保存在本机加密文件中，用于启动对应 Profile。

配置可恢复

每次写入 `config.toml` 前都会创建备份，出错后可恢复。

诊断可反馈

复制诊断信息时不会包含 API Key，方便在 Issues 中描述问题。

环境检查

先确认本机条件，再生成启动器。

App 会检查 Codex App、Codex 可执行文件、Node runtime、启动器目录和 Profile 目录。只有 CLI 缺失时通常仍可继续使用桌面多开功能。

常见问题

分发试用前先说清边界。

macOS 提示无法验证或应用已损坏怎么办？

请先确认从 GitHub Releases 下载最新签名版本。若旧包残留 quarantine 标记，可删除旧 App 后重新安装最新版；仍有问题请附版本号和系统版本提交 Issue。

是否支持 Windows？

支持。Release 同时提供 Windows x64 安装版与便携版；建议优先使用安装版，并确保已安装 Codex / ChatGPT 桌面 App。

第三方中转站都能用吗？

不保证。MVP 只支持 Responses 兼容接口，服务商需要真正支持 Codex 使用的 Responses API。

能接入智谱、DeepSeek、通义或 Kimi 吗？

可以先测试，但前提是服务商提供 OpenAI/Responses 兼容入口。只支持原生 API 或只支持 Chat Completions 的接口不一定可用。配置时重点确认 Base URL 是否通常以 `/v1` 结尾、API Key 是否支持兼容接口、模型 ID 是否是接口实际接受的名称。

反馈问题时需要提供什么？

请提供 macOS 版本、Codex App 版本、服务商名称、Base URL 是否以 `/v1` 结尾、Provider 测试错误信息，以及 App 内复制的诊断报告。
